# 智能钓鱼目标

外部 Agent 只提交数量；服务在机器人进程内执行。默认以当前地点为家，新钓到 8 条生鳕鱼/鲑鱼后带回家。不把旧库存、河豚、热带鱼、丢失的渔获或收竿成功本身计作完成。生鱼保留给猫；烤鱼不是完成条件，已有 `smelt` 动作用于明确需要烹饪的任务。

```sh
node scripts/fish.js start --count=8 --radius=128
node scripts/fish.js status
node scripts/fish.js cancel
node scripts/fish.js resume
```

机器接口：`tool.run fishing_goal {op:"start",args:{count:8}}`；只读状态为 `tool.dry observe_detail {what:"fishing"}`，返回参数 schema、目标、实际事实、下一决策、最近事件、路径与终态回执。`start` 接受可选 `home:{x,y,z}` 和搜索半径（默认 128 方块）；`resume` 沿用原家与已确认钓获，可用 `--radius=...` 调整补给范围。`cancel` 会收竿、停止移动，等当前操作确认退出后释放租约。

本地顺序：健康/受伤与水域风险 → 夜间返家睡觉 → 已达数量返家验证 → 饥饿 → 补给/空位 → 选岸 → 移动 → 抛竿/收鱼。受到自己的伤害事件或生命下降即中断，不等到濒死；返家后至少稳定 15 秒、生命至少 18 且附近无敌对生物才恢复。睡觉仅限主世界，确认 sleep/wake 事件。睡觉与收竿失败最多重试三次；其他失败保留具体诊断并阻塞，不能把启动当完成。

补给优先检查已加载、可达的储物箱；只存入明确列出的普通挖矿杂物，并遵守长期物品保留记录；取现成鱼竿、线和木棍，材料齐全时在可达工作台合成。不会拆玩家建筑取得木材。缺少可达补给会返回 `fishing_supplies_unavailable`、缺料和路径诊断；不假装能凭空造竿。

导航复用标准无挖掘陆路动作；跨水时，`navigation/journey.js` 用现有 Movements 生成楼梯/半砖路线，水面边经过完整通道验证，始终落到干燥实心地面，排除岩浆、未知方块、急流和潜水。不硬编码服务器坐标。

持久化在 `data/fishing-<worldId>.json`，原子写入、损坏拒绝启动，事件有界。热重载停止旧操作并从持久目标继续；断线暂停，重新连接后可 resume。未确认的中断渔获不会计数。背包中原始鱼、竿和材料通过 `task:fishing-inventory` 保留，完成后仍保留生鱼，自动进食/整理不能消费它们。

旧 `.autofish` 无限循环和只报告“开始”的同名工具已删除，统一使用目标接口。
